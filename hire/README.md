## Start with the problem — not a sales call

You can submit a **public-safe problem brief** through the repository’s **Hire D’AUBE** issue form.

Good examples:

- “We copy orders between a form, spreadsheet and chat by hand.”
- “We repeatedly create the same reports/content/assets and want a reusable workflow.”
- “A process has too many manual handoffs and errors.”
- “We need a small integration or automation, not a large custom software project.”
- “Our small shop website is hard to find and we do not know which SEO issue matters first.”

D’AUBE will use the information to determine fit and the smallest sensible next step. A request is not a purchase, invoice, contract or promise that D’AUBE will accept the work.

## What to include publicly

Safe useful information:

- the problem;
- desired outcome;
- how the process works today;
- approximate scope;
- whether timing is flexible or important;
- whether you are researching, deciding, or authorized to buy;
- whether you need a quote before deciding budget;
- a public website/page if relevant.

## Never post these in a public issue

Do **not** post:

- passwords, OTPs, API keys or recovery codes;
- private keys or production credentials;
- government-ID numbers/images;
- bank/card/payment details;
- private customer lists or customer personal data;
- confidential contracts or proprietary internal data;
- unrestricted administrator access.

If a real engagement later requires sensitive or contractual information, D’AUBE must move it to an appropriate authorized private channel.

## How D’AUBE qualifies requests

D’AUBE uses evidence rather than sales pressure. Signals include:

- whether the problem is concrete;
- outcome and scope clarity;
- delivery fit;
- budget readiness (it is okay to need a quote first);
- decision authority;
- safe/realistic access and trust boundaries.

A high score does not guarantee acceptance. Legal, security, capacity, funding and rights gates remain separate.
