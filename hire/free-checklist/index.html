Automation Audit Checklist

Use this before paying anyone to repair or expand a business automation. It catches the boring failure modes that become expensive later.

Quick check

  • What business event triggers the workflow?
  • Which systems does it read from and write to?
  • Who owns it and where are credentials stored?
  • What happens when authentication expires?
  • Can the same event run twice, and is it idempotent?
  • What happens on timeout, 429, 4xx or 5xx?
  • Is there a retry ceiling and recovery path?
  • Are sensitive values redacted from logs?
  • Can partial writes leave systems inconsistent?
  • Are success/failure events observable?
  • Is there a reproducible test fixture?
  • Are acceptance criteria written down?

Red flags

Silent failures, duplicate billing/messages, leaked secrets, uncontrolled retries, production writes without validation, missing ownership, and “works on my machine” with no reproducible evidence.

Minimum handoff

Ask for an architecture summary, configuration list, credential boundary, runbook, known limitations, monitoring, recovery steps, test evidence and acceptance criteria.
